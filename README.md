# 運行管理アプリ（白ナンバー安全運転管理者対応）

Next.js（App Router）製の運行管理アプリです。元の Google Apps Script 版と同じ機能
（運転日報／アルコール点呼、社用車台帳、運転者台帳、マスタ設定、ダッシュボード）を
Vercel にそのままデプロイできる構成にしています。

## 機能

- **運転日報**: 出発前／帰着後のアルコールチェック・点呼記録、走行距離の自動集計、点検写真の添付、CSV出力。車検・オイル交換・免許更新・アルコール検知のアラートを表示。
- **車両台帳（専用ページ。誰でも閲覧可、登録・編集・削除・取込・車検証の読み取りは管理者と整備士）**: カード一覧での車両管理、車検日・点検日・オイル交換目安・整備履歴の管理、CSV一括取込／出力、まとめて一括編集（CSV貼り付け編集）。車検証の画像も保存でき（管理者のみ閲覧。端末で約700KB以下のJPEGに圧縮し、KVの `fleet:shaken:v1:{車両ID}` に保存、車両側は `shakenFileAt` で有無を持つ。API は `/api/vehicles/[id]/shaken`）、カードの「📎 車検証を見る」でプレビュー・ダウンロード・削除ができる。車検証の読み取りは、文字の位置（座標）で項目名と値を組み合わせる（`lib/shaken-layout.ts`。PDFは pdf.js の文字位置、写真はTesseractの単語位置を使う）＋文章としての読み取り（`lib/shaken.ts`）の併用。見つからない項目は、型式・車台番号・メーカー名の形から補う。車検証と検査証記録事項は別々の書類として読み込め、画像も別々に保存する（`recordFileAt`、KV `fleet:shaken:v1:{車両ID}:record`、`/api/vehicles/[id]/shaken?kind=record`）。写真は「🤖 AIで読み取る」（`/api/shaken-ai`。管理者のみ。環境変数 `ANTHROPIC_API_KEY` が必要、モデルは `SHAKEN_AI_MODEL` で変更可（既定 claude-sonnet-5-5）。写真を Anthropic に送る。氏名・住所は取り出さない指示）でも読める。未設定のときはOCRだけを出す。車両カードの「車検証を見る」「記録事項を見る」や「📷 車検証」から、保存済みの画像を読み込んで読み取れる（`VehicleOcrModal` の `preload`）
- **AIアシスタント（管理者のみ）**: 画面の右下に浮かぶ「AIロボ」のボタン（現場管理アプリと同じキャラクター。長押ししてドラッグで移動でき、位置は localStorage `fleet:ai-fab`。スマホは下のバーの上に小さく出し、開いている間は隠す）から開くチャット（`components/AssistantButton.tsx`、API は `/api/assistant`）。質問のたびに、サーバーが最新の記録（車両・運転者の氏名／免許期限・直近の日報・給油・整備・レンタカー・予約・月ごとの合計。電話番号・免許証番号・社員番号・写真は除く。`lib/assistant-context.ts`）と「使い方」（`lib/help.ts`）を Anthropic Messages API に渡して答えさせる。変更はできない（読み取り専用）。環境変数 `ANTHROPIC_API_KEY`（必須）、`ASSISTANT_MODEL`（任意。無ければ `SHAKEN_AI_MODEL`、既定 claude-sonnet-5-5）、`ASSISTANT_DAILY_LIMIT`（1日の質問数。既定200。KV `fleet:assistant:v1:count:日付`）。
- **運転者ログイン・免許証写真からのOCR自動登録**: 「運転者としてログイン」画面から、運転者台帳の名前を選んでログイン（パスワード不要）。未登録の方は「免許証写真で自動登録」で登録すると、そのままログイン（ブラウザ内処理・外部送信なし）
- **運転者台帳（管理者限定・設定ページ内）**: カード一覧での運転者管理、免許種別・更新期日・連絡先の管理、CSV一括取込／出力
- **各種マスタ設定（管理者限定）**: 部署、確認者、確認方法、整備種別、タイヤ種別、免許種別をサブタブで切り替え、Excelからの改行貼り付けで一括登録、並び替え・五十音整列・個別編集
- **操作ログ・バックアップ（管理者限定）**: 日報・車両・運転者・マスタの登録／編集／削除、管理者ログイン／ログアウトを自動記録（最新500件）。ログCSV出力、全データJSONバックアップ、ログ消去が可能
- **使い方（Q&A）**: ヘッダーの「使い方」タブ。ログイン、運転日報、予約・アラート、給油台帳、レンタカー、整備台帳、設定、困ったときの対処をQ&Aにまとめている。キーワード検索と分類での絞り込みができる。内容は `lib/help.ts` にあり、画面の動作を変えたときはここも直す
- **ホーム画面アプリ（PWA）**: iPhone（Safari の「ホーム画面に追加」）と Android（Chrome の「アプリをインストール」）で、アプリのように使える。ストアへの申請は要らない。設定は `app/manifest.ts`、`public/sw.js`、`public/offline.html`、`public/icons/` にある。データ（`/api/`）は端末に残さず、常にサーバーから取得する。圏外のときは「オフラインです」を表示する
- **設定（旧「管理画面」を統合）**: 「⚙️ 設定」ページ（常に最後）に、メニューの並び替え（誰でも。端末ごとに「↑」「↓」で変更。`lib/menu.ts`、localStorage `fleet:menu:order`。下のバーには上から4つ）と、管理者向けのカードの登録・運転者台帳・各種マスタ設定・操作ログ／バックアップ・ロゴ／アイコンをまとめる（`components/SettingsTab.tsx`）。以前の「管理画面」タブは無くなった
- **カレンダー（専用ページ）**: 車両の使用実績・予約・レンタカーの予約を月表示（`components/CalendarTab.tsx` が `UsageCalendar` を載せる）。ダッシュボードには開くためのボタンだけ置く
- **カード貸出（ガソリンカード・ETCカード）**: 専用タブ（スマホはメニュー内）。カードの登録・貸出・返却・履歴を、本体データとは別のKVキー `fleet:cards:v1` に保存（`lib/cards-store.ts`、API は `/api/cards`・`/api/cards/loans`）。借りるには運転者ログイン、返却は誰でも記録可（記録者名を残す）、カードの登録・編集・削除は「⚙️ 設定」ページの「カードの登録」から管理者のみ（`components/CardsAdmin.tsx`。種類はドロップダウンのチェックで複数選べる（`kinds`。古いデータの `kind` も読める）。カードには事業部（任意。マスタの事業部から選ぶ）も登録できる）、貸出記録の削除は履歴から管理者のみ。返却予定日を過ぎた未返却は「返却期限超過」。使う車両はレンタカーのみ選べる（「レンタカー（車両の登録なし）」か、登録済みで利用中のレンタカー）。ダッシュボードに貸出中の一覧、履歴はCSV出力。カード番号は全桁を保存しない運用（識別番号は下4桁など）
- **整備士ログインのときのページ絞り込み**: 整備士だけでログイン（運転者も管理者もいない）のとき、メニュー（下のバー・左のパネル）は `MECHANIC_TABS`（ダッシュボード・整備台帳・車両台帳・使い方。`lib/menu.ts`）だけにし、設定は出さない（`Header` の `mechanicOnly`、`FleetApp` の `visibleTab` で、隠れたページを開いていたらダッシュボードに戻す）。整備士は車両台帳を管理者と同じく全部編集でき、`/api/vehicles/[id]/shaken`（画像の保存・閲覧・削除）と `/api/shaken-ai` は、管理者に加えて登録済みの整備士名（ヘッダー `x-mechanic`、画像の表示・ダウンロードは `?mech=`。`lib/mechanic-auth.ts`、クライアント側は `mechanicHeaders()`）でも使える。整備士ログインは名前選びなので強い認証ではない（車検証の画像は個人情報を含むため、ほかの端末でも名前を知られると見られる点に注意）。

- ヘッダーの「同期完了／同期中／同期エラー」チップでサーバー保存状況を表示

## データの保存先

- **Upstash Redis（推奨・本番用）**: Vercel の Marketplace から Upstash（またはVercel KV）
  を接続すると、環境変数 `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`
  （または `KV_REST_API_URL` / `KV_REST_API_TOKEN`）が自動設定され、データが永続化されます。
- **未設定の場合**: `/tmp` 内の一時ファイルに保存するフォールバック動作をします。
  Vercel の Serverless 関数はインスタンスが再起動すると消えるため、**本番運用では
  必ず Upstash Redis（またはVercel KV）を接続してください。**

1. このプロジェクトを GitHub リポジトリにプッシュします。
2. [Vercel](https://vercel.com) で「Add New... > Project」からリポジトリをインポートします
   （フレームワークは自動的に Next.js と認識されます。ビルド設定の変更は不要です）。
3. **データ永続化のため、Storage タブから Upstash Redis（または Vercel KV）を作成して
   プロジェクトに接続してください。** 接続すると環境変数が自動的に追加されます。
4. （任意・推奨）Project Settings > Environment Variables で以下を設定すると、
   アプリ全体に Basic 認証がかかり社外からのアクセスを防げます。
   - `BASIC_AUTH_USER`: ログインユーザー名
   - `BASIC_AUTH_PASSWORD`: ログインパスワード
5. **`ADMIN_PASSWORD` を設定してください。** 「各種マスタ設定」タブの編集はこのパスワードで
   ログインした管理者のみ行えます（未設定の場合、マスタ編集ができません）。
6. 「Deploy」をクリックすればデプロイ完了です。

CLIでデプロイする場合:

```bash
npm i -g vercel
vercel        # プレビューデプロイ

```

## 管理者ログインについて

「各種マスタ設定」タブは `ADMIN_PASSWORD` を知っている人だけが編集できます。
ログイン状態は httpOnly Cookie（8時間有効）で保持されます。

日報の新規登録（出発登録）・帰着登録・車両／運転者の登録・編集・CSV入出力は
管理者ログイン不要です。ただし、**帰着済み（確定済み）の日報の削除**は
記録改ざん防止のため管理者ログインが必要です（API側でも Cookie を検証しており、
未ログインではサーバー側で拒否されます）。登録済みの日報の**編集と帰着登録**（出庫中・帰着済みとも）は、管理者と
**記入した本人**（運転者ログイン。`x-driver-id` ヘッダーで日報の運転者IDと照合）だけができます。
他の運転者・未ログインはサーバー側で拒否されます（新規の出発登録は誰でも可能）。
本人による編集では、運転者は書き換えられません（操作ログには「日報編集（確定済み・本人）」と記録）。

## 操作ログ・バックアップについて

「操作ログ・バックアップ」タブ（管理者限定）では、いつ・誰が（管理者／利用者）・何を
（日報・車両・運転者・マスタの登録／編集／削除、管理者ログイン／ログアウト）行ったかを
自動記録し一覧表示します（最新500件を保持し、超えた分は古いものから破棄されます）。

- **⬇ ログCSV出力**: 操作ログをCSVでダウンロードできます。
- **📦 全データJSONバックアップ**: 日報・車両・運転者・マスタ・操作ログをすべて含む
  JSONファイルを1クリックでダウンロードできます。特に Upstash Redis 未接続時
  （`/tmp` フォールバック運用時）はデータが消えるリスクがあるため、定期的な
  バックアップを推奨します。
- **🗑 ログを消去**: 蓄積したログをまとめて削除できます（管理者ログイン必須）。

## OCRによる運転者の自動登録について

「免許証写真で自動登録」は [Tesseract.js](https://github.com/naptha/tesseract.js) を
CDN から読み込み、**ブラウザ内だけで**画像からテキストを抽出します（写真や読み取り結果が
外部サーバーに送信されることはありません）。氏名・免許証番号・有効期限を正規表現で
推測して自動入力しますが、手書き文字や照明条件によって精度が変わるため、
**保存前に必ず内容を確認・修正してください。**

## プッシュ通知の設定（任意）

アプリを閉じていても、スマホ・パソコンに通知を届ける機能です。設定しなくても、🔔の一覧は使えます。

1. パソコンで `node scripts/gen-vapid.mjs` を実行し、表示された `VAPID_PUBLIC_KEY` と `VAPID_PRIVATE_KEY` を、Vercel の Environment Variables に登録する（`VAPID_PRIVATE_KEY` は秘密。コミットしない）。
2. 毎朝9時ごろの自動通知を使うときは、`CRON_SECRET` も登録する（推測されにくい長い文字列）。Vercel が定期実行（`vercel.json` の crons）のときに、この値を付けて呼ぶ。未設定のときは、自動通知は動かない（外から勝手に送られないため）。
3. 再デプロイする。
4. 使う人が、「🔔 お知らせ」の「この端末で通知を受け取る」を押す。iPhone は、先に「ホーム画面に追加」して、そのアイコンから開く。
5. 管理者は、「🔔 お知らせ」の「テスト通知を送る」で、届くか確かめられる。

仕組み：通知の本文は暗号化して送らず、「新しいお知らせがあります」という合図だけを送る。端末のサービスワーカー（`public/sw.js`）が、合図を受けたら `/api/push/latest` から本文を取得して表示する。通知の送り先は、ブラウザ各社の公式プッシュサービスに限る。

## 現場管理アプリとの連携
- 現場管理アプリの案件の画面から「社用車管理」を押すと、出発登録が開き、行先にその現場名が入る（URLの `?site=` または署名付きチケット）。
- 同じ氏名の運転者がいれば、運転者のログインも引き継ぐ（`/api/sso`）。チケットは現場管理アプリが発行する60秒有効の署名付きで、社用車管理向け（種類 `s`）のものだけ受け付ける。
- 必要な環境変数：`SSO_SECRET`（現場管理アプリと同じ値、16文字以上。チャットには貼らない）。未設定・氏名が一致しない・同姓同名が複数のときは、通常のログイン画面になる。

## 帰着登録の夕方通知
`vercel.json` の crons で、毎日18時ごろ（UTC 09:00）に `/api/cron/return-check` を呼び、帰着登録がまだの車両があるときだけ通知する。`CRON_SECRET` が必要（朝のまとめと同じ）。Vercel の Hobby プランでは、実行は指定した時刻の前後1時間のどこかになる。
